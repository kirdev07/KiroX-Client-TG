# kiroX — утверждаемая спецификация интерфейса и миграции на Kotlin + TDLib

**Статус:** проект макетов для согласования с владельцем; не выдавать за реализованный или протестированный функционал.  
**Основа:** изучена кодовая база прежнего `kirdev07/KiroX-Telegram-client-Android` (главный экран, истории, меню создания, Dock, контакты, настройки, профиль, кастомизация и отчёты).  
**Новый проект:** Kotlin + Jetpack Compose + TDLib. Старый репозиторий только для изучения UX и оригинальных разработок, без записи и механического копирования GPL-исходников Telegram.

## 0. Главные правила для Codex

1. **Не начинай проект заново:** TDLib скачана, базовый Kotlin-проект, Splash и экран телефона уже существуют. Сначала исследуй текущий код/ветку/сборку, потом меняй точечно.
2. Этот документ задаёт **целевую UX-карту**, а не разрешение реализовать всё за один запуск. Делать только согласованный этап. В конце каждого этапа — debug APK, реальные проверки и остановка.
3. **Никаких новых названий дизайн-системы:** в пользовательском интерфейсе только бренд **kiroX** (или **KiroX** там, где необходимо). Не употреблять слово, от которого владелец ранее отказался, в новых экранах, описаниях и релизах.
4. Чёрный AMOLED `#000000` как тема по умолчанию, графит `#121212–#1B1B1B`, белые надписи, вторичный текст `#9A9A9A`, разделители `#222222`. Акцент — белый/графит; без цветных декоративных плашек и 3D. Цвет Telegram Premium — только если таков его реальный значок.
5. **Никаких фиктивных вызовов к Telegram:** TDLib как единственный источник реальных данных. Пока функция не подключена — честный экран-заглушка с пометкой «В разработке». Не подменять личные данные демонстрационными в живом аккаунте.
6. Демо-режим **строго изолирован**: только debug-сборка или явно отделённый тестовый профиль без Telegram-сессии. Тестовый код `12345` не должен открывать настоящие аккаунты. На тестовых экранах постоянный маркер «Демо».
7. Не пытайся обходить Premium, рекламные сообщения, правила Telegram или серверные лимиты. Собственные значки не являются официальной верификацией.
8. Соблюдать лицензию TDLib и всех зависимостей, не переносить GPL-исходники Telegram в независимую кодовую базу без отдельно проверенного лицензионного решения. Не публиковать репозиторий или APK без явного разрешения владельца.

## 1. Карта экранов и навигация

```text
Splash (существует) → Телефон (существует) → Выбор страны → Код / QR / 2FA и прочие состояния TDLib → Авторизован
                                                                  ↘ Демо (отдельная локальная ветка)

Главный контейнер: 4 фиксированные нижние вкладки
├── Контакты
│   ├── Контакты (поиск, написать, голосовой звонок, долгое нажатие для видео)
│   └── Звонки (журнал; Все / Пропущенные / Входящие / Исходящие)
│   └── «Пригласить друзей» внизу списка / пустого состояния
├── Чаты
│   ├── Архив      ← слева
│   └── Сообщения  ← справа и стартовая вкладка
│   ├── истории, поиск, папки, новые сообщения и групповые действия
│   └── Экран конкретного чата (другая навигационная глубина)
├── Настройки
│   ├── Кастомизация → Theme Studio, темы, Chat Studio, обои, Splash, Motion, профиль, Dock
│   ├── Чаты и папки → фильтры, архив, стикеры, эмодзи, поведение
│   ├── Уведомления; Конфиденциальность; Данные и память; Устройства
│   ├── Telegram Premium (настоящий статус Telegram)
│   ├── Возможности KiroX; Дополнительно; Обновления; О KiroX
│   └── Локальные настройки анимаций и значка пользователя
└── Профиль
    ├── Большой аватар, отображаемое имя + KiroX-значок + настоящие Premium/verification
    ├── Подпись «Пользователь KiroX», @username, о себе, день рождения (если доступен)
    ├── «Редактировать профиль», «Переключить аккаунт»
    └── Истории, медиа, Избранное, общий контент (при поддержке TDLib)
```

**Важное:** не добавлять отдельную нижнюю вкладку «Звонки» и центральную огромную кнопку карандаша. Нижняя навигация всегда: **Контакты · Чаты · Настройки · Профиль**. Старое поведение, при котором «Звонки» могли заменять «Настройки», **не переносим**: оно конфликтует с новой договорённостью. Журнал теперь находится внутри контактов.

## 2. Геометрия / дизайн-словарь

| Элемент | Предлагаемый размер/поведение |
| --- | --- |
| Основной горизонтальный отступ | 16 dp, для компактных строк допустимо 14–16 dp |
| Заголовки экранов | 25–27 sp, белый, `Чаты`, `Контакты`, `Настройки`, `Мой профиль`; не огромный логотип вместо названия |
| Иконки | контурные 22–24 dp, нажатие минимум 48×48 dp, все с `contentDescription` |
| Строка диалога | ориентир 68–74 dp, аватар 48–52 dp, две строки, состояние непрочитанных/закрепления |
| Нижняя панель | полноширинная, высота контента около 64–72 dp + системные inset, тонкая верхняя граница, 4 равные области |
| Вкладки Архив/Сообщения | чёрный фон, серый неактивный, белый активный текст, тонкая линия 1.5–2 dp **только** под активной надписью; без плашек |
| Переключения | 160–240 мс, прерываемые, уважать системный animator scale и Reduce motion |
| Скролл | без stretch/overscroll, истории и шапка не растягиваются, нижние строки не заходят под Dock |
| Списки | lazy/виртуализованные, стабильные id, отдельно хранить scroll state каждого раздела и аккаунта |
| Ошибки/пустые экраны | компактное сообщение + действие, без фальшивых успешных состояний |

## 3. Старт, ввод телефона, вход

### Splash (существует; не переделывать без отдельного согласования)
- AMOLED Black, слово `kiroX`, частицы, световые дуги, волнообразный индикатор.
- Надпись: **«Больше, чем мессенджер.»**; подпись: **«Скорость, удобство и свобода общения в одном приложении.»**
- Первый осмысленный сценарий анимации — около **2,5 с**, но **не блокировать готовый экран на обычном запуске**; возврат из фона без заставки; без анимаций, если они системно выключены.

### Телефон / страна (существуют, проверить текущий код)
- Автоопределение: сохранённый выбор → SIM → регион устройства → ручной выбор. Без геолокации и чтения контактов.
- Ввод международного номера распознаёт код страны, формат через libphonenumber; +7 может означать Казахстан либо Россию, не угадывать без уверенности.
- Экран выбора страны: поиск по названию/ISO/коду, флаги, выбранные/недавние, полный список.
- Ошибки, фокус, клавиатура, маленькие экраны и вставка номера проверяются.

### Код / безопасность
- Длина кода и каналы подтверждения определяются текущим состоянием TDLib, **не фиксировать 5 цифр для настоящего входа**.
- Отдельно обработать QR/подтверждение на другом устройстве, email, пароль 2FA, регистрацию, истечение/повтор кода, flood wait и отказ сети.
- Демо: тестовый код 12345, только локальная ветка. Реальную сессию демо не разблокирует.
- Не записывать номер, коды, ключи, хэши и сессии в логи/репозиторий.

## 4. Главная вкладка «Чаты»

### Шапка
- Заголовок **«Чаты»** слева.
- Кнопки справа: **Поиск**, **Отметить всё прочитанным**, **Карандаш** (меню создания).
- Поиск открывается кнопкой. Не закреплять постоянную крупную поисковую строку на главном экране без отдельного согласования.
- «Отметить всё прочитанным» показывает число бесед и подтверждение, меняет **только текущий раздел**, не все аккаунты и не все папки автоматически.
- Карандаш (только здесь, не в Dock): **Новое сообщение / Создать группу / Создать канал / Избранное / Секретный чат**. При отсутствии реализации соответствующего API — честная заглушка, без ложного успеха.

### Истории
- Горизонтальная полоса, первой **«Моя история»** с кнопкой `+`, видна даже без своих и чужих историй.
- Аватары около 52 dp, ненавязчивые кольца новых/просмотренных историй, состояния upload/loading/error.
- Нажатие на `+` → создание истории; на аватар с опубликованной историей → просмотр. Если TDLib-операции ещё не реализованы — пометить это, не имитировать публикацию.
- Лёгкая сезонная анимация **только в шапке** по настройке; останавливать при сворачивании/прокрутке/фоновой работе.

### Архив слева
- Порядок строго: **Архив | Сообщения** (в отличие от старых промежуточных версий).
- При старте выбран раздел **«Сообщения»**, правая вкладка.
- Свайп **вправо** внутри списка сообщений → **Архив**, свайп **влево** внутри архива → **Сообщения**.
- Переключение сохраняет Dock, текущий аккаунт и независимые позиции скролла, без отдельного full-screen fragment; два реальных списка TDLib: main/archive.
- Счётчики непрочитанных рядом с названиями, не декоративные.
- **Не добавлять строку «Архив чатов» в список сообщений**: архив уже в отдельной вкладке.
- Папки Telegram — отдельный слой фильтров, не переименовывать архив папкой и не ломать пользовательские фильтры.

### Список диалогов
- Каждая строка: аватар, имя, последнее содержимое (текст/медиа/пометка голосового), время, галочки/статус отправки, непрочитанные, mute, pin, черновик, упоминания где применимо.
- Клик → конкретный чат; долгий тап → contextual menu; свайп по строке (если настроено) → действие: прочитать/архивировать/закрепить и т.п.
- Отдельные настоящие данные для групп, каналов, ботов, Saved Messages, секретных чатов; не смешивать peer ids.
- Корректная загрузка из TDLib: пагинация, updates в реальном времени, переупорядочивание, обновление read/unread, пустой список, ошибка и offline.

## 5. Универсальные свайпы — явные приоритеты

**Не реализовывать один агрессивный `pointerInput` поверх всего приложения.** Приоритет по контексту:

1. Android edge-back и Back/gesture навигация, открытые модалки, клавиатура.
2. Жест сообщения/диалога (ответить, архивировать), горизонтальная карусель историй, слайдер/палитра/видео.
3. Внутренние переключатели раздела: `Архив ↔ Сообщения`, `Контакты ↔ Звонки`, вкладки медиа профиля.
4. Только затем переключение **корневых** вкладок.

Согласованная схема свайпов:
- Из **Сообщений** вправо → Архив, из **Архива** влево → Сообщения.
- Из **Архива** ещё вправо на свободной области → Контакты; из **Сообщений** влево на свободной области → Настройки.
- В Контактах: **Контакты** влево → **Звонки**, **Звонки** вправо → **Контакты**; после крайней вкладки свободный свайп может перейти в Чаты.
- Из Настроек: вправо → Чаты; влево → Профиль. Из Профиля: вправо → Настройки.
- Внутри **открытого чата** свайп вправо по сообщению — ответ, а не внезапный уход на архив/другую нижнюю вкладку.
- Свайпы между табами не должны удалять/архивировать реальные чаты сами по себе. Условия захвата: направление, порог движения, скорость и зона старта. При сомнении предпочитать безопасное отсутствие перехода; кнопки Dock всегда доступны.

## 6. Контакты и звонки

### Контакты
- Заголовок **«Контакты»**, поиск, добавление контакта.
- Внутри переключатель **Контакты | Звонки**, с сохранением выбора при возврате.
- В списке **только реальные Telegram-контакты**; локальная телефонная книга не подмешивается сюда.
- Справа каждой строки две независимые кнопки: **Написать** (существующая беседа или создание) и **Позвонить** (голосовой). Долгий тап на звонок или меню предлагает видео, если поддерживается; доступность зависит от приватности и TDLib.
- Нажатие на имя/аватар → профиль пользователя (определить единообразно); отдельные действия не конфликтуют.
- **«Пригласить друзей»** в самом низу / empty state, через штатный Android Sharesheet, без автоматической отправки SMS или скрытой синхронизации.

### Журнал звонков
- **Не отдельная нижняя вкладка**. Внутренний экран/раздел внутри Контактов.
- Все / Пропущенные / Входящие / Исходящие; дата/время, тип, видео/аудио, количество повторных вызовов.
- Соседние одинаковые вызовы одного участника можно компактно объединять с раскрытием подробностей, без утраты отдельной истории.
- Правая кнопка → повторный вызов; строка → детали/профиль, длинное нажатие → Позвонить / Написать / Профиль / Удалить с подтверждением.
- Использовать **данные Telegram/TDLib**, не Android `READ_CALL_LOG`.
- Внешние разрешения, VoIP, ограничения, данные звонков и работа в фоне требуют отдельного реального тестирования. Если звонки ещё не интегрированы — разметка остаётся демо, со статусом функции.

## 7. Настройки — только настройки приложения

Структура отдельной вкладки **«Настройки»** без огромного второго профиля:

- Вверху компактная строка активного аккаунта (маленький аватар, имя, переход в Профиль/переключение аккаунта).
- **Кастомизация** → Theme Studio (AMOLED Dark/Graphite Dark), свои темы, сохранение/импорт/экспорт, поиск параметров, Undo, превью; главный экран, нижняя панель, Chat Studio (пузыри/обои/шапка/поле ввода), Splash (частицы/сезоны/волна), профиль, анимации.
- **Чаты и папки** → папки, архив, параметры поведения, стикеры и эмодзи (не дублировать визуальные настройки Chat Studio).
- **Уведомления**, **Конфиденциальность**, **Данные и память**, **Устройства** (активные сеансы).
- **Telegram Premium** — только официальный статус/предусмотренные Telegram способы подписки. Не создавать «KiroX Premium», не заявлять бесплатное Premium.
- **Возможности KiroX** — каталог с честными статусами `Работает / В разработке / Недоступно`; без выдуманных «посетителей профиля».
- **Дополнительно** — язык, энергосбережение, блокировка приложения, отдельные настройки приватности и прочее по наличию реальных функций.
- **Обновления**, **О KiroX** — версия, changelog, лицензии, ссылки, разработчик, проверенный канал обновлений.
- Поиск по настройкам (реальный по категориям и названиям).

**Не переносить большое `Center Identity` в Настройки** — эта шапка теперь в Профиле. Не удалять возможности редактирования и переключения аккаунта: в настройках лишь короткие переходы.

## 8. Профиль — данные Telegram + локальный знак KiroX

- **«Мой профиль»**: аватар около 96 dp (опции 80/96/112 dp), изменение фото, имя, @username, статус, био, день рождения при наличии, истории, медиа, Избранное, редактирование, переключение аккаунтов.
- Крупный блок профиля по центру (бывшая идея Center Identity), без дубля в Настройках; сезонные частицы по настройке.
- Справа **отображаемого имени** — **собственный монохромный знак KiroX** в отличимом от официальной галочки шестиграннике. Рядом не подменять настоящую верификацию Telegram.
- Под именем компактная подпись **«Пользователь KiroX»**. Это **локальный UI-ярлык**, не серверный титул Telegram. Показывать по умолчанию в собственном профиле, возможность отключить в настройках. Не утверждать, что у других пользователей установлен KiroX — TDLib не даёт такой информации.
- **Premium:** значок только по реальному флагу `user.isPremium`; **верификация:** только по реальному полю `verificationStatus`, отображать независимо друг от друга и от знака KiroX. Не рисовать золотую звезду на обычном аккаунте.
- Доступность: подписи «Отметка KiroX (локальная)», «Telegram Premium», «Проверено Telegram» отдельно.
- Медиа/истории и остальные вкладки должны быть реальными или чётко помеченными «В разработке».

## 9. Экран переписки — отдельно после главного каркаса

Сейчас **НЕ требовать полного переноса**, но архитектурно предусмотреть:
- Шапка: назад, аватар, имя/статус, звонок/видео и меню.
- Сообщения: входящие/исходящие, метки времени, статусы, ответы, цитаты, реакции, медиа, фото/видео, документы, голосовые.
- Поле ввода: текст, вложения, эмодзи, отправка/запись, клавиатура/инсеты.
- Группы/каналы/боты/секретные чаты, темы/форумы и закреплённые сообщения требуют отдельных сценариев.
- Жест «ответить» приоритетнее горизонтальной навигации; оптимизация длинных чатов.
- Функции, неподдержанные текущей интеграцией, не имитировать и не включать без проверки.

## 10. Архитектура Kotlin + TDLib

Рекомендованные границы (подстроить под уже существующий проект):

```text
app/ navigation/ theme/ ui/{auth,home,contacts,calls,settings,profile,chat}
core/model/ — чистые модели и состояния (Account, Chat, ChatList, Story, CallEntry)
core/tdlib/ — один gateway Client, update dispatcher, account-scoped sessions
core/data/ — repositories TDLib → StateFlow, pagination, cache, update processors
core/demo/ — локальные фейковые данные без связи с Telegram
core/preferences/ — настройки оформления и жестов
```

- В `ViewModel` только UiState + пользовательские действия; не отправлять команды TDLib из Composable.
- Реагировать на `UpdateAuthorizationState`, `UpdateNewChat`, `UpdateChatPosition`, изменения последних сообщений, read counters, user/photo/status, stories и call updates (где поддерживаются конкретной зафиксированной версией TDLib).
- Корректно хранить два списка `ChatListMain` / `ChatListArchive` и `ChatListFolder` отдельно, позиции сортировки по TDLib, не по времени последнего сообщения самостоятельно.
- Проект Android должен собираться даже при временно отключённом demo или отсутствии реальной сессии, но не утверждать, что TDLib подключена, если только есть скачанные исходники.
- Для нескольких аккаунтов обеспечивать отдельные клиентские состояния, БД и настройки per-account; не показывать данные одного аккаунта при выборе другого.
- Ключи Telegram API, хранилище сессий и уведомления требуют безопасной конфигурации; sensitive данные не логировать. Проверить fingerprint подписи/дистрибуцию отдельно.
