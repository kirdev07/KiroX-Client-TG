# Codex — KiroX Kotlin: Этап A (только каркас главного интерфейса)

Новый проект уже создан, TDLib скачана, Splash и экран телефона перенесены. **Ничего не скачивай и не создавай заново без необходимости.**

Я прикладываю два обязательных файла:
- `KIROX_UI_SPEC.md` — полный источник требований, сценариев и тестов.
- `KIROX_INTERACTIVE_MOCKUP.html` — интерактивный офлайн-макет всех согласованных экранов. Открой его в браузере, изучи расположение элементов, состояния и переходы. PNG — дополнительные статичные ориентиры, при противоречии HTML и спецификация важнее изображений.

**Делай ТОЛЬКО этап A из документа:** добавь к уже рабочему проекту на Kotlin + Jetpack Compose каркас с 4 нижними вкладками (Контакты, Чаты, Настройки, Профиль), внутри чатов — `Архив | Сообщения` с архивом **слева**, истории с «Моя история +», заголовок «Чаты», поиск/прочитать всё/карандаш, списки демо-диалогов, контакты с быстрыми кнопками написать/позвонить, внутренний журнал звонков с фильтрами, экран Настроек и Профиль с локальным значком KiroX. Добавь переходы и основные согласованные жесты, учитывая конфликты жестов Android.

**Существующие экраны Splash, ввода номера и доступную TDLib-интеграцию не ломай.** Пока разрешены только явные **демонстрационные данные** с маркировкой «Демо». Код 12345 не должен авторизовывать настоящий аккаунт. Не создавай фиктивную успешную Telegram-авторизацию. Не подключай реальные звонки, истории, отправку сообщений, Premium, настройки аккаунта и синхронизацию без отдельного согласования. Неработающие действия показывают честное состояние «В разработке».

**Исправь известные расхождения:** не добавляй центральную кнопку создания, нижнюю вкладку «Звонки», дубль архива в списке, второй большой профиль в настройках и вымышленную подписку KiroX. Профильный знак KiroX должен быть отдельным от настоящих Telegram Premium/верификации и не менять серверные поля аккаунта.

После изменений:
1. Выполни Gradle sync / компиляцию и собери debug APK.
2. Проверь открытие всех экранов, горизонтальные переходы, работу Back, сохранение видимых вкладок и empty/error states; где нет эмулятора — честно пометь NOT TESTED.
3. Укажи точный путь к APK, список изменённых файлов, PASSED/FAILED/NOT TESTED и известные проблемы.
4. **ОСТАНОВИСЬ:** дальнейшие функции и полировка дизайна только после моего подтверждения.
