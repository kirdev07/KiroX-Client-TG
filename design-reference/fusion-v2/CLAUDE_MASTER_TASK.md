## 1. НЕИЗМЕНЯЕМЫЕ UX-КОНТРАКТЫ

### Темы

- Fusion Expressive: фиолетовый/сиреневый AMOLED, выразительные формы Material 3 Expressive, закруглённые контейнеры, плотные графитовые карточки, фиолетовые исходящие сообщения и умеренное свечение.
- Fusion Glass: navy/синий, настоящая прозрачность только там, где полезно, прозрачные bottom dock / sheets / cards, атмосферные картинки как user wallpaper, мягкие обводки и опциональный blur.
- В обеих темах **одинаковая навигация и семантика действий**, одинаковые данные TDLib, разные shape/color/background/animation render-strategies.
- Сохранять прежние AMOLED/Graphite/Midnight/Espresso палитры или обеспечить явную безопасную миграцию существующих preferences; не стирать настройки пользователя.
- Сразу предусмотреть Color/Shape/Type/Motion/Glass tokens: значения из `theme-tokens.json` — **предварительные**, окончательные цвета/радиусы сверять по изображениям.
- При Reduce Motion/Power Saver/low-tier: отключать тяжёлый blur, частицы и ненужную анимацию, использовать статические поверхности.
- Нельзя использовать чужой иллюстративный арт из AI-макета без проверки прав, стоков или собственных ассетов.

### Навигация — важнейшая точка согласования

**Визуально утверждённый dock:** `Чаты · Звонки · Истории · Настройки`.
**Существующий код:** `Контакты · Чаты · Настройки · Профиль`.

Предварительная карта, которую Claude обязан подтвердить владельцу в этапе A:
- Chats → настоящий список, фильтры, архив, новое сообщение, вход в контакты.
- Calls → существующий журнал и VoIP state, без фиктивных вызовов.
- Stories → реальные Stories TDLib, без фиктивных публикаций.
- Settings → настройки с профилем/управлением аккаунтами в верхней карточке; полный экран контактов через новый чат/поиск, а также доступен из профиля/контекстных маршрутов.
- Собственный профиль, настройки приватности, аккаунты, контакты и Избранное **не теряют доступность**.
- Заменять корневые вкладки только после UX routing-map и согласования владельца; затем обновить документацию и тесты.

### Telegram и безопасность

- TDLib — источник истины. Ни один demo/mocked repository не должен заменить реальные чаты, контакты, звонки, истории, папки, медиа, Premium или Verification.
- Действия должны отражать ответы API: никогда не показывать «Отправлено»/«Опубликовано»/«Создано» до подтверждения.
- Безопасная обработка токенов, номера, пароля 2FA, ключа TDLib, пути БД; никаких секретов и пользовательских данных в git/logs.
- Для звонков сохранять один VoIP engine instance и lifecycle; переключение темы не запускает новый звонок.
- Для аккаунтов сохранять изоляцию сессий, каталогов TDLib, настроек, уведомлений, скролла и файлов. Не переключать аккаунт в неподходящий момент, не терять черновик.
- Реальные удаления/сбросы/приглашения/публикации на тестовом аккаунте — только с явным решением владельца и подтверждениями в UI.
- Group calls / screen sharing отложены за 1.0 по существующей release-документации. Дизайн их не санкционирует как готовую функцию.

## 2. АРХИТЕКТУРНАЯ ЦЕЛЬ

Не ломать существующее разделение:
- `com.kirox.app.ui.theme.FusionTheme` — расширить как единый контейнер `KiroXVisualStyle` с двумя новыми вариантами и legacy handling. Material 3 Expressive API применять только если версия библиотеки из `libs.versions.toml` его реально поддерживает; иначе использовать совместимые кастомные Compose-компоненты.
- `com.kirox.app.settings.KiroXSettingsRepository` — хранить тему/акценты/эффекты в текущем DataStore, миграция enum names и дефолтов без перетирания прошлых значений.
- Единые переиспользуемые UI primitives: AppTopBar, PillTabs, FusionDock, Avatar, ChatRow, MessageBubble, MediaCard, FormField, GlassPanel, ModalSheet, Empty/Loading/ErrorState. Названия адаптировать под проект, если аналоги уже существуют.
- `TelegramMainScreen`, `TelegramChatScreen`, `AccountScreens`, `CallScreen`, `CallsAndStories` — минимальные, ревьюируемые правки.
- ViewModels/Repositories продолжают посылать UiState, Compose рисует. Не отправлять TDLib команду из random Composable side effect, где повторная композиция вызовет повтор отправки.
- Распознавать wide >=600dp; использовать существующий `FusionNavigationRail` и правильные system bar / IME insets.

## 3. ПЛАН А–H С ВОРОТАМИ ПРИЁМКИ

### Этап A — аудит, скриншоты, карта маршрутов (БЕЗ production-кода)

**Задачи:** проверить актуальную ветку/исходники, Gradle/config, наличие существующих экранов, состояния UI/TDLib и доступность дизайнов. Снять существующие скриншоты/видео, если подключён телефон/эмулятор. Составить матрицу 46 композиций на тему: reuse/adapt/create/not supported; указать source files и приоритеты.

**Особое внимание:** текущие AccountsSheet vs placeholder в меню Profile, read/search, calls background behavior, Stories posting, folder editing, forum topics, video/media screens, четыре существующие палитры, необходимость навигационного перехода. Обязательно проверить действительную версию проекта и работоспособность baseline в доступной среде.

**Отчёт:** `docs/design/fusion-audit-A.md` — route graph before/after, список затрагиваемых классов, риски, ответы API/пробелы, схема data migration, скриншоты и TESTED/NOT TESTED. Без установки/записи реальных данных без разрешения.

**Gate A:** владелец утверждает карту маршрутов и приоритеты; до этого **не переписывать навигацию**.

### Этап B — тема, токены, persistence и glass fallback

**Задачи:** расширить `FusionTheme`, подключить оба style renderer; создать общие primitives, Typography/Shapes/Motion/Surface; добавить safe DataStore миграцию и live preview/persist choice; на старых Android поставить недорогое статичное стекло без эффекта blur.

**Отчёт/тест:** смена темы из settings без сброса сессии; прежние палитры/настройки не ломаются; UI smoke-тест на 360/412dp; Compose preview в обеих темах.

**Gate B:** владелец визуально проверяет foundations до массового рефакторинга.

### Этап C — shell/nav + главный экран + контакты/поиск

**Задачи:** после Gate A реализовать нижнюю навигацию, маршрут контактов/профиля, шапку KiroX, поиск, Stories row, список/папки/архив, placeholder/loading states; Contacts UI и глобальный поиск разделить на честные TDLib scopes. Сохранить скролл и выбранные вкладки.

**Проверки:** каждый старый destination достижим; долгие списки, свайпы, back/keyboard, fold/wide; нет fake active tabs. Не смешивать архив с папками и не превращать глобальный поиск в только SearchChats, если результат подписан «Глобальный».

**Gate C:** владелец утверждает полное совпадение главной композиции в двух темах.

### Этап D — переписка, Media Studio и вложения

**Задачи:** 8 Media Studio композиций + существующая переписка: пузыри, обои, сообщения, вложения/attachment sheet, фото viewer, video player, голосовые, GIF/emoji/sticker picker, файлы и shared media. Не внедрять тяжёлые проигрыватели «для красоты» без реального источника файлов.

**Проверки:** отправка/получение через тестовый аккаунт (если разрешено), длинная история, reply/edit/forward/delete с подтверждением, фото/видео/GIF и большие файлы, onPause/cancel, без двукратной отправки и подвисаний при смене темы.

**Gate D:** скриншоты диалогов и медиа в обоих стилях плюс реальные тесты или точное NOT TESTED.

### Этап E — профили, группы, каналы, форумы и папки

**Подэтапы:** E1 собственный профиль + карточка другого пользователя + contacts; E2 создание/инфо групп и каналов; E3 форумные темы (реальные API/ID и permissions); E4 настройка/редактирование папок (существующее create/delete сохранить).

**Проверки:** отсутствие фиктивных Premium/Verified, group admin rights, ссылки каналов, forum topics с правильными ID; недоступные действия — disabled с объяснением; folder edits не удаляют чаты.

**Gate E:** четыре микро-отчёта E1–E4 и общее подтверждение этапа.

### Этап F — Stories: лента, просмотр, редактор, приватность

**Задачи:** все 4 композиции в обеих темах; использовать `TelegramStoryRepository` и `StoryPost.kt`; отдельный UI state для загрузки, видео, replies/reactions, выбора аудитории и редактирования (по реальным API). Новые функции без API должны показывать неподдерживаемое состояние, а не отправлять фиктивную историю.

**Проверки:** просмотр и mark read, закрытие, пауза/видео, загрузка, ошибка, безопасная публикация в тестовый аккаунт при разрешении, переключение темы без сброса очереди.

**Gate F:** реальные/NOT TESTED статусы каждого action и визуальное сравнение.

### Этап G — звонки: журнал, входящий, audio/video, мини-окно

**Задачи:** сохранить существующие `TelegramVoipRepository`, `CallScreen`, NativeCall/tgcalls, медиа-движок и историю. Добавить только требуемые визуальные состояния и mini call overlay; Android PiP — только при подтверждённой технической совместимости/жизненном цикле. Нельзя имитировать видеопоток макетной картинкой.

**Проверки:** реальный двусторонний audio/video (если окружение/разрешение доступны), входящий при foreground/background/lockscreen, разрешения, Bluetooth/headset, reconnect, повторные вызовы, app background. НЕ заявлять PASS без телефона.

**Gate G:** владелец визуально проверяет экраны, а реальные медиатесты отдельно отмечены.

### Этап H — авторизация/аккаунты/настройки + итоговая регрессия

**Подэтапы:** H1 оформление Splash / welcome / phone / code / 2FA / QR и двух новых тем; H2 список/переключение/добавление аккаунтов с изоляцией; H3 финальная settings/appearance studio, анимации и media preview; H4 полный regression/test pass и issue list.

**Проверки:** правильная длина кода из TDLib; пароль не логируется; QR/email/flood wait/отмена, 1→2→1 аккаунта (при разрешении); notification scoping; темы и черновики переживают перезапуск; backstack и реальная навигация.

**Gate H:** CI/test logs + APK только из реально успешной сборки, скриншоты обеих тем, performance/accessibility review, стабильное обновление поверх прошлого APK. **Никакого auto-merge**; владелец принимает отдельное решение о merge/release.


Матрица тестирования:
- Android minSdk 29, Android 10–17 по мере наличия устройств/эмуляторов; 360×640dp, 412×915dp и >=600dp;
- fontScale 1 / 1.3 / 2; TalkBack / contentDescription / keyboard focus;
- navigation gestures / 3-button / IME / permission denial;
- без сети, медленная сеть, reconnect, process recreation / foreground-background;
- два аккаунта, переключение тем, downgrade fallback glass, Reduce Motion / power saver;
- screenshot golden compare на согласованных ключевых экранах, не утверждать pixel-perfect без точного оригинала;
