# KiroX Fusion UI — контакты, поиск, карточка пользователя

**Статус:** VISUALLY APPROVED — все 8 предложенных композиций для обоих стилей утверждены владельцем 29 октября 2026. Реализация в коде и интеграционные тесты не выполнены.
**Темы:** Fusion Expressive (фиолетовая), Fusion Glass (сине-стеклянная).
**Эталон:** концепт из беседы ChatGPT от 29 октября 2026 с 8 экранными композициями для каждого стиля. Само сгенерированное изображение хранится отдельно в беседе — не выдавать описание за точную пиксельную копию.
**Важно:** текущая нижняя навигация отличается от концепта, поэтому не переключать корневые маршруты без согласования и сохранения доступа к аккаунту, контактам, Stories и звонкам.

## 01. Контакты

- Заголовок «Контакты», поиск, навигация назад или в главное меню согласно конечному роутингу.
- Вверху отдельные действия «Новый контакт» и «Пригласить в Telegram».
- Далее список реальных контактов Telegram: фото/инициал, имя, достоверный онлайн-статус, алфавитная индексация при необходимости.
- Нажатие на контакт открывает карточку. Действия звонка / сообщения доступны там, где есть реализация.
- Долгое нажатие не должно запускать разрушительные действия.
- Expressive: насыщенная тёмная база, фиолетовый активный пункт, округлые мини-контейнеры.
- Glass: сине-стеклянные поля поиска и строки, сохранение читаемости поверх фонового изображения.

## 02. Глобальный поиск

- Один поисковый вход и категории «Все», «Люди», «Чаты», «Каналы», «Сообщения».
- Локальная и глобальная выборки не должны смешиваться без явных секций. Реальные результаты из TDLib с отсечением устаревшего ответа при смене запроса.
- При поиске по сообщениям — подсветка совпадений, контекст, переход к найденному сообщению.
- Пустые запросы / загрузка / ошибки / офлайн должны быть различимы.
- В концепте пример запроса «Ан» с результатами; эти имена/аватары — только иллюстрация, не база настоящего аккаунта.

## 03. Карточка пользователя

- Большая аватарка/обложка, имя, реальный статус. Кнопки «Сообщение», «Позвонить», «Видео» (только при поддержке), «Ещё».
- Контактная информация: Telegram username, bio, настройки уведомлений; телефон только при наличии прав доступа/доступности.
- Раздел «Общие медиа» с типами фото, файлы, ссылки, голосовые; реальные вложения TDLib.
- Состояния для бота, пользователя, приватного профиля, несуществующего/заблокированного контакта.
- Не создавать локальную «верификацию» как будто она серверная. Premium показывать только при реальном флаге Telegram.
- Expressive: выразительная фиолетовая подложка и капсулы кнопок; Glass: фотофон, мягкие полупрозрачные модули.

## Дополнительные экраны на визуальном листе (также утверждены визуально)

4. Меню действий над контактом: поделиться, редактировать, удалить, заблокировать, управлять уведомлениями (подтверждения для опасных действий).
5. Добавление контакта: имя, фамилия, номер, опциональное фото, сохранение через реальный API.
6. Создание группы: название, участники, настройки приватности/истории в соответствии с TDLib.
7. Создание канала: название, описание, публичность/ссылка, подписчики, история.
8. Медиа пользователя: общие фото/видео/файлы, сетка с просмотром оригинала.

Эти пять макетов также **утверждены визуально** вместе с остальными экранами комплекта. Утверждение дизайна не означает, что все функции Telegram уже реализованы.

## Визуальные параметры и единые компоненты

- Использовать существующий `FusionTheme` и токены из `theme-tokens.json`. Слои Glass должны иметь непрозрачный fallback без размытия.
- Сохранять композицию выбранного эталона, единые размеры кнопок >=48dp, динамический шрифт, системные Insets, TalkBack.
- Плавные переходы аватара и карточки 180–300мс, остановка ненужной анимации по Reduce Motion.
- Экранное содержимое из единого реального слоя TDLib; никаких DEMO-данных в реальной сессии.
- Не копировать компоненты/ресурсы Yougram; сравнение — визуальный ориентир, реализация оригинальная.

## Работа Claude Code — после визуального согласования, поэтапно

1. Изучить существующие `TelegramMainScreen.kt`, `AccountScreens.kt`, `TelegramChatScreen.kt`, TDLib модели контактов и маршруты.
2. Подготовить карту текущих экранов и отличия нового макета.
3. Разработать переиспользуемые компоненты, не дублируя state/repositories между Expressive и Glass.
4. Подключать функции только к реальным методам TDLib; если метода/функции нет — обозначать честное неподдерживаемое состояние.
5. Провести проверку обоих стилей (360dp/412dp/планшет, 130–200% шрифта, IME, жесты, пусто/загрузка/ошибка) и сохранить скриншоты.
6. После каждого этапа — SHA коммита, список изменений, PASSED/FAILED/NOT TESTED и остановка для утверждения владельцем.
