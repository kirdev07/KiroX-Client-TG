# KiroX Fusion Stories — дизайн для согласования

**Статус:** DRAFT / НЕ УТВЕРЖДЕНО. 29 октября 2026 г.
**Ветка:** `design/kirox-fusion-expressive-glass`
**Основа:** ранее утверждённые темы `Fusion Expressive` (фиолетовый, Material 3 Expressive) и `Fusion Glass` (сине-стеклянный, атмосферные обои).

## Цель

Добавить единый, выразительный UX историй, который использует **реальные данные Telegram TDLib**, без переноса чужого кода и без фиктивной публикации. Экраны обеих тем имеют одну и ту же структуру, но различаются оформлением фона, глубиной поверхностей, интеракциями и световыми акцентами. Новый дизайн пока только обсуждается.

## 01 — Истории / главная

- Верхний заголовок `Истории`, поиск (если реализован), компактное меню.
- Верхняя горизонтальная лента с круглой `Моя история +` и реальными аватарами, видимыми статусами просмотрено / не просмотрено.
- Чипы-фильтры `Все / Контакты / Каналы` и вертикальные компактные карточки историй (автор, время, thumbnail, статистика только для своих историй при наличии данных).
- Нижний dock как в утверждённом макете (`Чаты / Звонки / Истории / Настройки`), но схема переходов требует сопоставления с текущей навигацией; контакты и профиль остаются доступными.
- Пустой список показывает полезное состояние, а не выдуманные истории.

## 02 — Просмотр истории

- Контент fullscreen c системными safe-area; сверху сегментированный прогресс по кадрам, назад/закрыть, аватар, автор, время и дополнительные действия.
- Тап слева/справа — предыдущая/следующая история; удержание — пауза; свайп вниз — закрыть; жесты не конфликтуют с Android back.
- Снизу: поле `Ответить...`, реакции (в том числе доступные аккаунту), отправка. Отклик виден только после подтверждения Telegram.
- Учитывать отключение звука, видео, загрузку, удаление, истечение срока и ограничение приватности.
- Переключение темы не пересоздаёт очередь истории и не теряет прогресс.

## 03 — Редактор истории

- Выбор фото/видео из системного picker; реальный media URI, не хардкод.
- Холст со светлым/тёмным контрастным scrim, верхние действия `Закрыть / Сохранить`, недеструктивные инструменты: текст, стикер, рисование, обрезка; доступность функций определяется фактической реализацией.
- Поле подписи, кнопка `Далее`; видео имеет видимый прогресс и корректный контроль аудио.
- В Fusion Expressive — фиолетовые выделения и плотные округлые панели. В Fusion Glass — голубые полупрозрачные панели, опциональный blur только для кнопок, не размывать сам контент.

## 04 — Публикация и приватность

- Мини-превью выбранного медиа, блок `Кто увидит` с реальными вариантами TDLib (конкретные значения проверить в текущей версии API).
- Контроль комментариев/ответов и сохранения только если Telegram это поддерживает и пользователь может менять.
- Подтверждение `Опубликовать` с понятными состояниями uploading / retry / error / completed. Нельзя показывать успех до ответа TDLib.
- Возврат к редактору, сохранение черновика только если реализовано, корректная обработка отмены публикации.

## 05 — Позже, отдельным согласованием

Полноэкранные видеоистории, множественные истории, сохранение, viewer для каналов, статистика собственных историй, список просмотревших, архив, истории в профиле, меню жалобы, недоступные истории, ошибки/сеть, низкая память.

## Визуальные стили

**Fusion Expressive:** фон от #080710 до #24123B, акценты #A276FF и #7354D8, активные капсулы, округления 16–28dp. Нижняя полоса ответов читабельная на ярких фото. Аккуратные spring-переходы 150–280мс.

**Fusion Glass:** фон от #071424 до #244A75, акценты #6B91FF и #9A83FF, стеклянные панели rgba(34,59,92,0.52), запасной непрозрачный режим на слабых устройствах. Прогресс, текст, реакции должны контрастировать с картинкой; blur на полноэкранном видео не применять.

Сохранить те же размеры контролов (>=48dp touch), табы, структуру и семантику. В обеих темах поддержать Reduce Motion, системные отступы, клавиатуру, TalkBack и выбор акцентного цвета в пределах стиля.

## Реализация для Claude Code — только после утверждения

1. Проверить фактическую интеграцию TDLib Stories в текущем коде: `CallsAndStories.kt`, `StoryPost.kt`, слой `telegram/`; зафиксировать реализованное / недоступное.
2. Сопоставить экран Stories с текущей архитектурой и навигацией, не потерять контакты/профиль и состояние сессии.
3. Добавить одну логику экранов с двумя render-вариантами темы через действующую `FusionTheme`, а не дублировать хранилища.
4. Сначала список и просмотр, потом редактор и публикация, затем визуальные проверки и реальные тесты.
5. После этапов — скриншоты APK в обеих темах, тесты и отчёт PASSED/FAILED/NOT TESTED, остановка для проверки владельцем.

**Важно:** визуальная генерация — только ориентация по стилю. Прямое заимствование чужой графики или кода Yougram запрещено. Нельзя считать макеты Stories утверждёнными без отдельного явного подтверждения пользователя.
