## Принципы ведения этапов

1. Не переписывать проект с нуля без необходимости; использовать уже работающие компоненты.
2. Не отмечать функцию «готово» только потому, что у неё есть экран или демо-заглушка.
3. Не подключать «бесплатный Premium», обходы серверных ограничений или фиктивную авторизацию.
4. Код KiroX пишется самостоятельно; сторонние клиенты — только функциональный ориентир, их код не копируется.
5. Для завершённого этапа фиксировать результаты сборки, тестов и оставшиеся ограничения.
6. Обновлять этот документ по мере реального прогресса, а не по первоначальным обещаниям.
