# План перехода DEMO → рабочая версия

Каждый этап завершается сборкой, unit-тестами и ручной проверкой на устройстве владельцем проекта. Реальная авторизация выполняется только владельцем.

## Этап A — архитектура и безопасность
- **Задачи:** application-scoped `TelegramClient` (suspend `send`, `SharedFlow` обновлений, close/recreate); разделение `TdlibClientManager` на репозитории; `allowBackup=false`/исключение `tdlib/`; ключ шифрования БД через Keystore; `SetLogVerbosityLevel`; навигация с back stack и графами auth/main; `FusionTheme` + токены (без редизайна — только замена литералов); fix lint (`values-v27`, исключение `TdApi.java`); JDK 17 в `gradle.properties` (`org.gradle.java.home`) или документировать; x86_64 `.so` для эмулятора; README сборки TDLib.
- **Зависимости:** нет.
- **Риски:** миграция незашифрованной БД на шифрованную (существующие тестовые сессии) — допустимо пере-логиниться; регрессия навигации.
- **Готовность:** один клиент на процесс (проверено повторным входом в Activity), `lintDebug` без ошибок, unit-тесты на маппинг auth-состояний и сортировку чатов через фейковый `TdClient`.
- **Проверка:** unit + инструментальный `TdlibNativeLoadTest`; `adb shell run-as … ls files/tdlib`; Auto Backup не включает `tdlib/`.

## Этап B — авторизация
- **Задачи:** все состояния (`WaitPhoneNumber…Ready`, `LoggingOut`, `Closed` → recreate); QR-вход; восстановление 2FA; показ Terms of Service при регистрации; FLOOD_WAIT и прочие ошибки локализованы; таймер повторной отправки (есть незакоммиченный); `LogOut`; индикатор соединения.
- **Зависимости:** A.
- **Риски:** блокировка номера при частых попытках (тестировать на тестовом DC `useTestDc=true` в debug), неверная обработка `SESSION_PASSWORD_NEEDED`.
- **Готовность:** вход по коду, по коду+2FA, по QR, выход и повторный вход без перезапуска приложения, перезапуск сохраняет сессию.
- **Проверка:** ручной сценарий-чеклист + unit на state machine; тестовый DC.

## Этап C — данные аккаунта
- **Задачи:** профиль (GetMe + фото через `FileRepository`), контакты (`GetContacts`, `UpdateUser`, статусы), список чатов с пагинацией, архив, папки (`UpdateChatFolders`, `ChatListFolder(id)`), mute/unread/mentions/черновики, состояния загрузки/пусто/ошибка/offline; реальные экраны Контакты/Настройки/Профиль на общих компонентах; `AccountManager` (мультиаккаунт — можно отложить до после F).
- **Зависимости:** A, B.
- **Риски:** производительность при 1000+ чатах; расхождение порядка чатов.
- **Готовность:** порядок чатов совпадает с официальным клиентом; аватары загружаются; >100 чатов подгружаются; переключение папок.
- **Проверка:** сравнение с официальным клиентом на тестовом аккаунте; macrobenchmark прокрутки.

## Этап D — сообщения
- **Задачи:** `MessageRepository`: `OpenChat/CloseChat`, `GetChatHistory` с пагинацией, `UpdateNewMessage/MessageContent/Edited/Deleted/SendSucceeded/Failed`, `ViewMessages`; отправка текста, ответ, редактирование, удаление (для себя/для всех), пересылка, вложения (фото/файлы/голос — поэтапно), статусы доставки; stateless `ChatScreen` из DEMO-версии с `reverseLayout`.
- **Зависимости:** C (пользователи, файлы).
- **Риски:** дубли/потеря сообщений при временных ID (`SendSucceeded` меняет id), память на длинных историях.
- **Готовность:** двусторонняя переписка, корректные статусы, история 10k сообщений без лагов.
- **Проверка:** тестовый аккаунт ↔ второй аккаунт; unit на редьюсер обновлений сообщений.

## Этап E — звонки и истории
- **Задачи:** история звонков через `SearchCallMessages` (MessageCall: направление, длительность, пропущен, видео-флаг) с группировкой по датам; кнопка звонка — открыть системный/официальный клиент или «недоступно» до появления VoIP; отдельное исследование tgcalls/WebRTC (лицензии, размер). Истории: `UpdateChatActiveStories`, просмотр (`GetStory`, `OpenStory`), без публикации на первом шаге.
- **Зависимости:** C, D.
- **Риски:** VoIP — крупная отдельная разработка; видео/групповые звонки не обещать.
- **Готовность:** реальный журнал звонков совпадает с официальным клиентом; истории контактов просматриваются.

## Этап F — удаление DEMO
- По `DEMO_REMOVAL_PLAN.md`, шаги 1–5. **Зависимости:** B, C, D подтверждены.
- **Риск:** случайное удаление переиспользуемых UI-компонентов — минимизируется шагом изоляции.
- **Готовность:** в release-APK нет `core.demo`, нет кнопки DEMO; старые DEMO-файлы очищаются при обновлении.

## Этап G — финальный UI/UX
- Утверждённая концепция нижней панели, `FusionTheme` AMOLED + Graphite, переключатель темы, единые компоненты, свайпы чатов, поиск, empty/skeleton-состояния, адаптация ≥ 600 dp.
- **Зависимости:** A (токены), согласование дизайна. Можно частично параллельно с C–E.
- **Готовность:** скриншот-тесты (Paparazzi/Roborazzi) для ключевых экранов в обеих темах.

## Этап H — тестирование и релиз
- Unit (репозитории, редьюсеры), UI-тесты Compose на фейковых репозиториях, Macrobenchmark + Baseline Profile, R8 с keep-правилами `org.drinkless.tdlib.**`, проверка ANR/StrictMode, Android 6–16, жестовая/3-кнопочная навигация, шрифт 130%, TalkBack.
- **Готовность:** release-сборка с R8 проходит smoke-тест входа и переписки; нет крашей в 30-минутном monkey-тесте; холодный старт измерен и зафиксирован.

## Порядок и параллельность
`A → B → C → D → F → H`; `E` после `D`; `G` (токены — в A, редизайн — после утверждения) параллельно с C–E.
