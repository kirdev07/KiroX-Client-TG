## High

### H1. Нет уведомлений о новых сообщениях
- **Файлы:** `app/src/main/java/com/kirox/app/voip/CallController.kt`, `voip/CallService.kt` — единственные места, где создаются уведомления (`NotificationCompat`, `notify`). `telegram/TelegramMessageRepository.kt:112` обрабатывает `UpdateNewMessage` только для открытого чата.
- **Причина:** обработка `UpdateNewMessage` / `UpdateActiveNotifications` TDLib для уведомлений не реализована.
- **Последствия:** при свёрнутом приложении пользователь не узнаёт о входящих сообщениях. Для мессенджера это главный сценарий.
- **Исправление:** включить уведомления TDLib (`option notification_group_count_max`), обрабатывать `UpdateNotificationGroup` / `UpdateActiveNotifications`, канал «Сообщения» с группировкой по чатам, действия «Ответить» и «Прочитано», учёт настроек звука/mute чата (`UpdateChatNotificationSettings`).
- **Проверка:** свернуть приложение, написать с другого аккаунта → уведомление с текстом, тап открывает чат; mute-чат не звенит.
- **Статус:** исправлено: уведомления TDLib + статус «не в сети» в фоне; проверено на телефоне (`6aa8b43`).

### H2. Входящие звонки и сообщения не приходят, когда процесс выгружен
- **Файлы:** `app/src/main/java/com/kirox/app/push/KiroxPush.kt`.
- **Доказательства (лог 2026-10-25):** `RegisterDevice(FCM)` → `400 APP_PUSH_APIKEY_MISSING`; `RegisterDevice(SimplePush)` и `RegisterDevice(WebPush)` приняты (`PushReceiverId`), но после выгрузки процесса ни один push на звонок/сообщение до ntfy не дошёл (кроме одного служебного сразу после регистрации).
- **Причина:** Telegram не отправляет push в Firebase-проект неофициального api_id; Web Push/SimplePush через UnifiedPush по факту не доставляются.
- **Последствия:** при выгруженном системой приложении звонки и сообщения пропускаются.
- **Исправление:** (а) проверить Web Push повторно с корректным шифрованием подписки (RFC 8291) и с паузой, пока сервер считает сессию офлайн; (б) запасной вариант — постоянное соединение в foreground-службе с низким приоритетом, по выбору пользователя («Надёжная доставка» в настройках уведомлений); (в) явно сообщить ограничение в бете.
- **Проверка:** `am kill com.kirox.app` → звонок/сообщение с другого аккаунта → уведомление.
- **Статус:** открыто (ограничение задокументировано в бете).

### H3. Анимация шапки постоянно грузит процессор
- **Файлы:** `ui/components/SceneClock.kt`, `ui/components/SeasonalLayer.kt`.
- **Доказательство:** замер на телефоне — экран «Чаты» с анимированной шапкой: **~35% CPU** при 30 кадрах/с, 0% задержанных кадров (`dumpsys gfxinfo`, `top`); в фоне 6%.
- **Причина:** часы сцены тикают 30 раз в секунду, пока шапка видна, — то есть всё время, пока открыт список чатов.
- **Последствия:** заметный расход батареи и нагрев при простое на главном экране.
- **Исправление:** для шапок 15–20 кадров/с; пауза анимации через N секунд без касаний; полная остановка в режиме энергосбережения (сейчас там только «лёгкий» режим).
- **Проверка:** повторить замер `top` / `gfxinfo` до и после; цель — <10% CPU в простое.
- **Статус:** исправлено: 36% → 0% CPU в простое (замер на телефоне) (`664f18b`).

## Medium

### M1. Гонка при запуске TDLib
- **Файл:** `telegram/TelegramClient.kt:44` — `start()` проверяет `if (client != null) return` без синхронизации; вызывается из главного потока (`TelegramViewModel.kt:18`), из потока Firebase (`KiroxPush.wake`) и из диспетчера TDLib (`dispatch`, после `Closed`).
- **Последствия (не воспроизведено):** при одновременном push и открытии приложения возможны два экземпляра TDLib на одной базе → ошибка блокировки базы.
- **Исправление:** `synchronized`/`AtomicReference.compareAndSet` при создании клиента.
- **Проверка:** unit-тест с параллельным вызовом `start()`; ручной — push во время старта.
- **Статус:** исправлено: `@Synchronized start()` (`f3c6474`).

### M2. Звонок может «соединиться» без звука, если движок ещё не загружен
- **Файлы:** `KiroXApplication.kt:19` (загрузка `libkiroxvoip` в отдельном потоке), `telegram/TelegramVoipRepository.kt` (`mediaAvailable` → ветка без движка ставит `CallPhase.Active`).
- **Последствия (не воспроизведено):** звонок в первые ~1–2 с после холодного старта или входящий сразу после запуска — экран «идёт разговор» без звука.
- **Исправление:** дожидаться завершения загрузки движка перед `CreateCall`/`AcceptCall`; в release ветку «без движка» не показывать как соединение.
- **Статус:** исправлено: ожидание загрузки движка перед звонком (`56503aa`).

### M3. Экран звонка не показывает переподключение и состояние собеседника
- **Файл:** `ui/call/CallScreen.kt` — поля `CallPhase.Active.reconnecting`, `remoteMuted`, `signalBars` из `TelegramVoipRepository` в UI не используются.
- **Последствия:** при потере сети пользователь видит идущий таймер и думает, что связь есть.
- **Исправление:** статус «Переподключение…», индикатор качества связи, пометка «у собеседника выключен микрофон».
- **Статус:** исправлено: «Переподключение…», плохая связь, выключенный микрофон собеседника (`b35e24a`).

### M4. Реакции в переписке отключены
- **Файл:** `ui/chat/TelegramChatScreen.kt:213, 223` — `onReaction = {}`, `reactions = false`.
- **Статус:** исправлено: реакции добавляются и снимаются, проверено на телефоне (`29f133b`).

### M5. Нельзя отправить видео и голосовое
- **Доказательство:** в коде нет `InputMessageVideo`, `InputMessageVoiceNote`; `ChatScreen` показывает «Голосовые сообщения появятся позже».
- **Статус:** голосовые — `6bbe8e8`; отправка видео — `29f133b` (на аккаунте не проверялась).

### M6. Лишняя регистрация FCM при каждом входе
- **Файл:** `push/KiroxPush.kt` — `registerAll()` всегда вызывает `RegisterDevice(FCM)`, Telegram каждый раз отвечает `APP_PUSH_APIKEY_MISSING`.
- **Исправление:** не регистрировать FCM, пока Telegram его не принимает (флаг после первой ошибки).
- **Статус:** исправлено: FCM не повторяется после отказа до следующей версии (`b35e24a`).

### M7. Размер APK 55 МБ — ИСПРАВЛЕНО (batch 6): нативные библиотеки сжаты в APK, скачивание 26 МБ; на телефоне запускается (проверено)
- **Доказательство:** `libtdjni.so` 34,5 МБ (уже без отладочных символов), `libkiroxvoip.so` 15 МБ; библиотеки лежат в APK несжатыми.
- **Исправление:** (а) сжатие `.so` в APK (`packaging.jniLibs.useLegacyPackaging = true`) — меньше размер скачивания, больше место после установки; (б) убрать из движка групповые звонки/демонстрацию экрана, ThinLTO (попытка была начата и откачена по просьбе владельца).
- **Проверка:** размер APK и размер после установки до/после; звонок работает.
- **Статус:** открыто.

### M8. На аккаунте остаётся «мёртвая» сессия удалённой версии
- **Доказательство:** при входе 2026-10-25 код пришёл в удалённую debug-версию; Telegram не предложил SMS.
- **Исправление:** экран «Устройства» (активные сеансы, завершение) — входит в список 21 пункта (№ 5).
- **Статус:** экран «Устройства» добавлен — сессию можно завершить (`04d48ae`).

### M9. Не собирается вариант `releaseCheck`
- **Доказательство:** `./gradlew assembleReleaseCheck` → `:app:processReleaseCheckGoogleServices FAILED`.
- **Причина:** у `releaseCheck` пакет `com.kirox.app.check`, а в `app/google-services.json` такого приложения нет; плагин Firebase применяется ко всем вариантам.
- **Исправление:** отключить задачу google-services для `releaseCheck` (Firebase там не нужен) или добавить пакет в консоли Firebase.
- **Проверка:** `assembleReleaseCheck` проходит.
- **Статус:** исправлено: `assembleReleaseCheck` PASS (`2f29a58`).
